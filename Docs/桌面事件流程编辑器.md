# 桌面事件流程编辑器原型

这份文档记录已移除的早期原型。当前工作台和流程格式见 [Flow Studio 使用说明](FlowStudio使用说明.md)。

> 这是第一版海洋场景演示。当前纯 UI 工具请使用 `FlowStudio.unity`，见 `Docs/FlowStudio使用说明.md`。

## 打开与试玩

1. 打开 `Assets/Scenes/TabletopFlowPrototype.unity`，也可使用菜单 **White Whale → 打开流程测试场景**。
2. 双击 `Assets/Settings/Flow/MonkeyIsland.asset`，打开流程图；菜单入口为 **White Whale → 桌面事件流程编辑器**。
3. 在场景中选择 `TabletopEventFlow`，编辑器会自动关联运行实例。也可以将该对象拖进窗口顶部的“运行实例”。
4. 进入 Play。岛屿在船前方，正常操作帆绳航行靠近，会触发事件。

测试快捷键（仅此测试场景）：

- **F6**：将船移到岛屿触发范围内。
- **F7 / F8**：报告战斗胜利 / 失败，检查对应出口。
- **F5**：还原事件、将船移回起点，重新开始。
- **Esc**：释放鼠标，以便操作编辑器窗口。

战斗尚未实现敌人和实际胜负判定。当前 `FlowBattleGate` 是独立战斗的入口，可由后续战斗系统接收 `onBegin` 并报告结果。

## 当前事件

开始 → 航行阶段 → 等待靠近岛屿 → 对话占位（直接通过）→ 一只猴子进入房间 → 设置是否战斗 → 分支。

- 是：启动战斗 → 等待结果 → 胜利结束 / 失败结束。
- 否：直接结束。

将“本事件是否战斗”节点的条件值取消勾选，即可体验没有战斗的路径。

岛上有三只新建的 `IslandMonkey.prefab` 实例。靠近后其中一只改变位置、尺度、外观和物理状态，成为房间里的猴子；其 GameObject、Item 和实例身份保持不变，岛上剩下两只。

新预制体基于原场景猴子构建，保留动物标签、灵活移动、捕捉交互和推挤能力。原猴子未配置 Sprite，因此新预制体使用临时几何外观。测试场景使用现有岛礁，关闭其他岛礁并调整该岛位置；原场景和原资源不受影响。

## 编辑流程

- 拖动节点标题移动位置；滚动条浏览画布。
- 使用“添加节点”或画布右键添加节点。
- 点击源节点右侧出口，再点击目标节点左侧入口，创建连线。同一出口重新连接会替换旧线。
- 选中节点，在右栏编辑参数或断开出口；Esc 取消待连接状态。
- 支持撤销、重做；点击“保存”将流程保存到资源文件。
- “检查流程”检查连线、入口、不可达节点、循环和参数。关联实例后，同时检查场景绑定。
- 运行时，黄色标识当前节点，绿色标识已完成节点，失败时当前节点显示红色。右栏显示运行记录。
- 运行中编辑的图在下一次重新开始时生效，当前执行使用开始时的独立快照。

第一版支持单条活动执行路径、条件分支和汇合，不支持循环和并行执行。连续动作可在同一帧完成，等待类节点会保留执行位置直到条件成立。

## 场景绑定

流程资源通过绑定名引用场景对象，不直接保存跨场景的对象引用。`FlowRunner.bindings` 提供对应关系：

- `playerShip`：实际海洋船。
- `island`：靠近检测目标点。
- `monkey`：要进入房间的那只猴子。
- `roomMonkeyPoint`：房间落点。
- `battle`：独立战斗入口。

关联运行实例后，节点中的绑定字段可以从下拉框选择。所有距离使用真实海洋单位，当前桌面显示比例为 1:20；不是桌面上的物理距离。

“生成物件”节点选择预制体与落点，并提供本次运行中的结果绑定名。它的生成物归本次事件管理，停止或重新开始时清理。当前预检查要求普通节点引用预先存在的场景绑定；暂不支持后续节点将生成结果作为必需的场景绑定。

## 生命周期与实现位置

- `FlowGraph`：流程定义、连线和静态校验。
- `FlowGraphWindow`：编辑窗口，使用 Unity 内置 IMGUI，不增加依赖包。
- `FlowRunner`：开始、推进、完成、失败、取消；运行状态与共享资源分离。
- `FlowContext`：本次运行的场景引用、条件、桌面阶段及清理动作。
- `FlowNodes`：具体节点的参数与执行逻辑。
- `FlowTransferable`：同一物件从海洋到房间的表现切换及还原。
- `FlowBattleGate`：事件与战斗之间的边界。
- `FlowPrototypeControls`：此测试场景专用的调试操作。

完成或失败后保留当前场景结果供观察；停止、重试或禁用运行器时，撤销转移、清理事件生成物并重置战斗入口。

这是事件生命周期原型。永久奖励、存档恢复、整次挑战的失败保留策略、战斗内容、全局桌面暂停和并行事件尚未接入。F5 还原本事件和船的位置，不代表完整的新一轮挑战，也不会重建火炮安装与冷却状态。

测试场景把房间和海洋保存在同一个独立场景中，沿用显示组件现有接口，避免改动主场景的加载结构。后续接入正式流程时，再将海洋加载与显示职责拆开。

## 验证入口

`FlowPrototypeBuilder.BuildAndVerify` 在独立 Unity 进程中生成场景和资源，并检查触发、猴子唯一性、胜负、非战斗分支、取消恢复、无效图和缺失绑定。

`FlowPrototypePlayVerification.Start` 进入实际 Play 模式，以正常航行触发事件，检查显示绑定、胜负、重试、生成清理、等待时长、运行快照及运行错误，并输出 `Captures/FlowPrototypePlayVerification.txt` 与前后截图。

生成器会重建测试资源，应只在确实需要重建原型时显式调用。日常编辑直接使用已保存的场景和流程资源。
