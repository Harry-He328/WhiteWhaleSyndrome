# White Whale Syndrome 玩法系统文档

本文说明游戏的系统结构、物件交互、房间与桌面玩法及游戏循环。具体物件、事件和关卡内容不在本文中列举。

## 一、系统结构

游戏采用第一人称视角，一个封闭的房间作为游戏的全部空间。

房间内包含：

- 解谜机关：若干，各有独立解法，直接与物件系统交互。
- 主要桌面：一张，承载航行和海战玩法。桌面是一个微型海洋，玩家的船在其中航行。
- 整理桌：一张，供玩家摆放、整理物件。目前没有其他玩法桌面。
- 装饰和家具。

玩家进行桌面玩法时，仍处于房间中的第一人称视角，从桌面前看向微型海洋并操作船。

房间道具、机关零件、桌面物件、船和船上的部件属于同一类实体：物件。

## 二、物件系统

### 2.1 物件

物件包含房间道具、机关零件、桌面物件、船和桌面中的物体，也包含槽。物件的属性由统一的 label（标签）子系统管理。

物件可以附着在其他物件上，表达局部交互位置。属于物件不代表一定可以拿取；是否可拿取、是否具有物理表现等能力按具体需要决定。

同一个物件可以从桌面进入房间，位置改变后仍是原来的物件，不会因此复制出另一个同时存在的物件。

#### 基础数据

物件目前包含以下基础数据：

- 名称。
- label 列表，由统一的 label 子系统查询和修改。
- 外观引用：使用的 Sprite 或形状渲染组件。
- 存续时间：无限，或剩余秒数。
- 可选的到期产物列表：记录生成哪些物件及各自的数量。

#### 存续时间与到期处理

大部分物件的存续时间为无限，此时不进行倒计时。设为具体秒数后开始倒计时，并允许随时修改：无限改为 10 秒时，从修改时开始计时；倒计时中可重新设置剩余秒数，也可改回无限并停止倒计时。

倒计时结束后，先执行到期处理，再移除原物件。到期产物列表为空时，原物件直接消失；列表有内容时，先生成指定种类和数量的物件，再移除原物件，可以产出一个或多个物件。

计时和到期处理先由物件自身负责，到期处理先使用一个普通函数，默认读取产物列表生成物件；后续如有特殊需求，再增加相应处理。同一次到期处理只执行一次，避免重复生成。

### 2.2 槽

槽是物件的一种子类，通过独立的“槽”label 表达其接收、组织物件交互的能力，使用统一的物件与 label 机制。这里的子类指设计分类，具体代码是否采用继承留到实现计划阶段确定。

槽可位于物件、家具、桌面或场景固定结构上，也可嵌套。附着在物件上的槽随所属物件移动。槽的外观依据具体交互需要决定，大部分不呈现为凹槽或插孔。

槽可以组织一个或多个物件参与同一次交互。交互效果根据接收方及参与物件的 label 和对应规则决定，不再以独立的“槽种类”规则体系表达。槽 label 表达组织交互的能力，具体组合条件与效果由相应规则定义。

能够承载物件的普通位置，不因此成为槽。槽也不统一具有存放、固定容量或被占满的性质。交互后物件是否留下、消耗或发生其他变化，由具体交互规则决定。

### 2.3 标签

label（标签）由统一子系统管理，用于描述、管理和查询物件属性，只用于系统判定，是物件交互逻辑的依据。

交互规则根据参与物件的 label 定义。新增交互效果可以单独实现对应逻辑；已有规则应能通过赋予相应 label 复用，不要求每个接收物件或槽重复配置同一规则。

### 2.4 拿取与摆放

玩家只能把物件拿在手里，同时只能拿一个，没有随身收纳方式。

物件可以放在任何平面上，包括地面。普通摆放不需要槽，也不因此触发槽的交互规则。

物件不会因拿取或摆放而永久丢失。按交互规则消耗或按存续时间到期移除属于正常玩法变化。

### 2.5 物件交互

基本操作是拿起物件，将其放到接收物件所在的位置。接收方可以是普通物件，也可以是具有槽 label 的物件。效果由接收方及参与物件的 label 和对应规则决定。

交互不限于两个物件。槽可以组织多个物件共同满足组合条件后产生效果。哪些物件属于本次交互、如何确定参与范围及何时触发，由具体交互规则明确，不能仅凭其他位置存在所需 label 的物件就判定条件满足。

不适用的物件也允许放入槽，但不会产生交互效果。

例如，在假设的清洁交互中，一张纸是物件，纸上污渍所在区域也是附着在纸上的物件，可以具有槽 label 及相应的可清洁属性；将带有清洁 label 的湿布放到该区域，可以清除污渍。这个例子仅用于说明物件、槽与 label 的关系，不作为具体物件或机关的设定。

### 2.6 其他操作

航行与攻击允许有用途明确的专门操作：旋转船舵、拉绳收放大帆，以及拉动小火炮模型的击发拉环。这些操作不要求转换为拿起物件、放进槽的形式，具体规则见第四章。

战斗中另有物件直接作用于对象的交互规则，见 4.3。

### 2.7 知识驱动

不主动暴露交互规则或提供解法引导，玩家通过观察、尝试和结果反馈发现规则。对规则的理解是玩家成长的一部分。

## 三、房间部分

### 3.1 解谜机关

- 若干，参考 Rusty Lake 系列的解谜机关。
- 机关之间通过物件依赖形成推进关系，所需物件从其他解谜机关或桌面玩法中产出。
- 玩家访问顺序自由。

### 3.2 资源管理

资源同样视作物件，分为两类：

- 传统类型资源：金币堆、水等。
- 功能性资源：用途普遍的物件，例如木板、炮弹、渔网等。

生命值不作为物件。船具有生命值，生命值作为船的状态存在，见 5.3。

桌面玩法中维持玩家生存的资源暂定为水：

- 水可以作为正常物件进行交互，也可以被使用、消耗。
- 常规消耗暂有两种候选方式：按时间消耗，或按行动次数消耗。目前尚未选定，不代表两者同时存在。
- 使用水以及某些特殊情况也会造成水的消耗。
- 该生存资源耗尽时，桌面挑战失败。

### 3.3 桌面与房间映射

桌面玩法的一些状态或事件即时反映到房间中，形成物件、槽、空间状态或视觉效果。玩家在房间侧通过物件交互做出回应，可以影响桌面内容。

映射也可以表现为同一个物件从桌面进入房间。例如，猴子从桌面里跳出来，在房间中活动；猴子作为物件始终只有一个，进入房间后不再同时存在于桌面中。玩家在房间中用渔网捕捉的就是它本身。

其他映射示例：

- 船受到攻击后，房间对应位置出现破损，玩家需要用木板在对应位置修补。
- 特殊攻击可以使房间出现破洞。长期未处理会导致进水，进水持续过久会使挑战失败。

玩家离开桌面时，桌面玩法继续运行。船按照当前帆的状态、舵角和航行状态继续运动，玩家需要在航行、战斗和房间内的处理之间安排操作。

## 四、桌面部分

### 4.1 航行与移动

玩家通过操帆和船舵，以模拟古代帆船的方式控制船的航行与转向。

- 大帆位于房间中，高度接近房高。玩家通过帆绳操作收起、落下大帆。
- 收帆使船减速，最终停船；落帆使船开始航行。
- 船舵位于主要桌面前，玩家旋转船舵控制转向。
- 玩家松手或离开后，帆和船舵保持当前状态。船继续按当前航行状态运动，舵角不会因玩家离开而自动回正。

持续航行使玩家能够离开桌面，去其他位置拿取物件或处理房间中的特殊情况，同时仍需考虑船的航行和战斗状况。

### 4.2 战斗

桌面战斗为 3D 平面海战。

- 玩家移动遵循航行与船舵控制逻辑。
- 攻击有范围和角度限制，沿船上火炮的固定方向射击。玩家通过操船调整攻击位置和朝向，不需要单独瞄准。
- 玩家通过桌面前沿的小火炮模型手动开火：拉动连接击发机构的拉环，触发船上火炮射击。
- 敌人的出现与行为参考类吸血鬼幸存者游戏。
- 战斗期间，玩家还需要处理房间中的意外情况。

### 4.3 战斗中的物件交互

战斗中还有直接作用于战斗对象的物件交互规则。玩家拿起物件，直接放到战斗对象上，物件在放下时对当前对象产生效果，不要求经过具有槽 label 的物件。

作用对象分为四类：

- 海洋：将物件放进海里，改变海面环境并产生对应效果。
- 地形障碍：物件产生礁石、雾区、洋流等效果，改变地图。
- 敌人：将物件放到敌人上，改变敌人状态或直接造成伤害。
- 自身船：将物件放到自己的船上，改变船的状态或产生对应效果。

具体物件对各类对象的效果另行定义。

### 4.4 玩家操作

桌面驾驶和攻击使用以下装置：

- 大帆与帆绳：控制航行与停船。
- 船舵：控制转向。
- 小火炮模型与击发拉环：手动开火。

操作这些装置前，玩家必须先放下手中物件。

装置布置在主要桌面附近，兼顾房间空间、视觉表现与操作便利。大帆主要利用竖向空间，布置时应避免遮挡桌面视线和房间通行。收放帆需要有明确的动作反馈，基础驾驶操作保持简洁，给玩家处理房间事件留出操作余地。

## 五、游戏循环

### 5.1 推进与胜利

桌面玩法推进 → 获得解谜相关物件 → 房间解谜 → 获得桌面玩法相关物件 → 继续推进桌面玩法。

桌面玩法由剧情驱动，采用不包含随机内容的线性流程，玩家失败后重复挑战。

房间解谜的理论最快进度受桌面玩法进度限制：玩家需要通过桌面玩法获得对应的解谜物件。桌面玩法通关代表获得全部解谜所需物件，桌面玩法可重复游玩。

游戏的胜利条件是完成全部房间解谜。

### 5.2 失败后的重置与保留

当前规则：桌面挑战失败后，桌面相关部分重置，房间解谜进度保留。

物件是否保留按用途决定，与其来自哪里、当前位于哪里无关：

- 解谜相关物件保留，已完成的解谜进度保留。
- 用于永久强化玩家的物件保留；物件使用后已经生效的永久强化也保留。
- 其他物件、本次桌面挑战中的临时升级和状态重置。

**待考虑：后续可能改为纯线性存档模式。目前仍保留上述重置与保留规则，尚未决定更改。**

### 5.3 失败条件

桌面挑战有三类失败条件：

1. 生存资源耗尽：维持玩家生存的资源暂定为水，耗尽时失败。
2. 海战失败：玩家的船具有生命值，生命值耗尽、船被摧毁时失败。
3. 房间情况导致失败：房间中的危机未及时处理，达到相应失败条件。例如，特殊攻击导致房间破洞，长期未修补会进水，进水持续过久导致失败。

第三类的具体事件及其失败条件另行定义，破洞进水是其中一个例子。

## 六、玩家体验目标

1. 桌面玩法和房间操作的边界模糊，事件和操作能在两边产生直接影响。
2. 知识驱动，玩家通过摸索理解物件交互和机关规则。
3. 资源和时间管理，包括为离开桌面、拿取物件和处理房间情况安排时机。
4. 桌面玩法与房间解谜的进度相互影响。
